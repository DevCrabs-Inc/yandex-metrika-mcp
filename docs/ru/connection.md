# Подключение аккаунта

## Вход через браузер

1. Попросите ассистента подключить Метрику или вызовите `metrika_connect`.
2. Откройте полученную ссылку `http://127.0.0.1:…/connect/…`. Она одноразовая и действует 10 минут.
3. На локальной странице описано, какой доступ запрашивается (только чтение, право `metrika:read`) и куда пойдут данные. Нажмите «Войти через Яндекс».
4. Подтвердите доступ на странице Яндекса.
5. Отметьте счётчики, которые будут доступны ассистенту через это подключение.

Код авторизации и токен не проходят через чат: их получает локальный процесс сервера. Токен сохраняется в системном хранилище паролей. В чат возвращается только `connection_id`.

Из терминала то же самое делает команда `npx -y @devcrabs/yandex-metrika-mcp auth login --alias "Клиент А"`.

## Несколько аккаунтов

У каждого входа свой `connection_id`. Каждый вызов инструмента явно указывает подключение и счётчик, поэтому данные разных аккаунтов не смешиваются. Даже если один счётчик доступен через два аккаунта, кэш, выгрузки и файлы у них раздельные.

```bash
npx -y @devcrabs/yandex-metrika-mcp auth list
npx -y @devcrabs/yandex-metrika-mcp auth allow conn_abc 12345678 87654321   # ограничить счётчики
npx -y @devcrabs/yandex-metrika-mcp auth allow conn_abc                     # снять ограничение
```

## Готовый токен

Если у вас уже есть OAuth-токен с правом `metrika:read`, сохраните его командой ниже. Ввод скрыт, токен можно передать и через stdin.

```bash
npx -y @devcrabs/yandex-metrika-mcp auth import-token --alias "Мой сайт"
```

Для серверов и контейнеров подойдёт переменная окружения `YANDEX_METRIKA_TOKEN`. Она создаёт подключение `conn_env` и нигде не сохраняется. Ограничить счётчики для него можно переменной `YM_MCP_ALLOWED_COUNTERS=123,456`.

## Своё OAuth-приложение

Обычно оно не нужно. Если хотите использовать собственное:

1. Зарегистрируйте приложение в Яндекс ID с доступом «Яндекс Метрика: получение статистики, чтение параметров своих и доверенных счётчиков» (`metrika:read`).
2. Добавьте Redirect URI `http://127.0.0.1:47613/callback`, `http://127.0.0.1:47614/callback` и `http://127.0.0.1:47615/callback`. Порты можно поменять переменной `YM_MCP_OAUTH_PORTS`.
3. Передайте серверу `YM_MCP_CLIENT_ID=<ClientID>`. Секрет приложения не нужен и не используется: вход идёт по PKCE.

## Хранение токенов

| Система | Хранилище                               |
| ------- | --------------------------------------- |
| macOS   | Связка ключей (Keychain)                |
| Windows | Диспетчер учётных данных                |
| Linux   | Secret Service (GNOME Keyring, KWallet) |

Если системного хранилища нет (например, Linux без графической оболочки), сервер откажется сохранять токен и объяснит причину. Незашифрованный файл с правами только для вашего пользователя включается явно: `YM_MCP_SECRET_STORE=file`.

## Истечение и повторный вход

Когда Яндекс перестаёт принимать токен, подключение получает статус `needs_reconnect`. Ассистент предложит `metrika_connect` с тем же `connection_id`: выгрузки и выбор счётчиков сохранятся. Бесконечных повторов и «вечного входа» нет.

## Отключение

`metrika_disconnect` или `auth logout <connection_id>`:

- отменяет выгрузки этого подключения;
- удаляет токен и кэш;
- блокирует подключение.

Готовые файлы выгрузок остаются до конца срока хранения. Отозвать доступ приложения в самом Яндексе — отдельный шаг: удалите приложение в настройках Яндекс ID, в разделе приложений с доступом к аккаунту.
