# Экспорт

`metrika_export_report` выгружает все строки отчёта в фоне. Ответ сразу возвращает задание (`job_id`), а за прогрессом ассистент следит через `metrika_get_job`.

## Форматы

| `format`         | Для чего                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------- |
| `csv`            | UTF-8, стабильный порядок колонок, экранирование по RFC 4180                                |
| `csv_excel_safe` | То же плюс BOM для Excel и защита от формул в текстовых ячейках (`'=`), отмечена в manifest |
| `json`           | Точные значения: целые числа больше 2^53 записываются строкой без потери точности           |

Для каждой группировки в CSV две колонки: название (`ym:s:…`) и идентификатор (`ym:s:…:id`). Затем идут метрики по их ID.

## Повтор и продолжение

- При создании выгрузки обязателен `idempotency_key`. Повтор с тем же ключом и теми же условиями вернёт то же задание. С тем же ключом и другими условиями — ошибку `IDEMPOTENCY_CONFLICT`.
- Каждая страница данных (до 5000 строк) сохраняется отдельно с контрольной суммой. После сбоя сети или перезапуска задание получает статус `interrupted` и продолжает работу с последней сохранённой страницы: `metrika_export_report` с `connection_id` и `resume_job_id`.
- Если данные изменились между страницами (поменялось число строк или выборка), выгрузка начинается заново. Повторное изменение даёт статус `partial` без готового файла.
- Повтор одной и той же страницы и ранняя пустая страница останавливают выгрузку ошибкой, а не тихой дедупликацией.

## Готовый файл

Файл публикуется атомарно: сначала пишется во временную папку, затем считается SHA-256 и переносится на место. Рядом лежит `manifest.json`, в котором указаны:

- условия отчёта;
- число строк;
- признаки качества;
- интервал получения данных;
- применённые преобразования.

Путь к файлу есть в `metrika_get_job` (`file_path`). Прочитать файл через ассистента можно с помощью `metrika_read_artifact` или ресурса `metrika://artifacts/<id>`.

## Хранение и лимиты

| Параметр                          | Значение |
| --------------------------------- | -------- |
| Размер одной выгрузки             | до 1 ГБ  |
| Всё управляемое хранилище         | до 2 ГБ  |
| Срок хранения файла               | 7 дней   |
| Минимум свободного места на диске | 200 МБ   |

Список выгрузок выводит команда `npx -y @devcrabs/yandex-metrika-mcp jobs`, удалить просроченные — `jobs clean`. Если файл нужен дольше, скопируйте его в свою папку.

Выгрузка идёт, пока работает процесс сервера. Отдельной фоновой службы нет. Чтобы прерванные выгрузки продолжались при следующем запуске автоматически, включите `YM_MCP_AUTO_RESUME=true`.
